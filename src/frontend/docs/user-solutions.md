# Пользовательские решения

`/cases/:id/work` открывает файловое рабочее пространство на локальных моках.
Компактные вкладки «Задание», «Файлы», «Результаты» расположены вплотную над
первой панелью. Справа — редактор с вкладками документов, breadcrumbs и строкой
состояния. Между панелями расположен доступный разделитель: он меняет их ширину
без пересоздания документов CodeMirror. На узкой доступной области панели
располагаются вертикально, информационный блок можно свернуть. Размер учитывает
ширину раскрытого sidebar, а не только ширину окна браузера.
Отправка и меню «Код» расположены в верхней панели рабочего пространства. Компонент `SolutionWorkspaceComponent`
принимает кейс, владельца, старую запись и чек-лист; внешний контейнер отвечает
за маршрут, mock-сессию и обновление шагов.

CodeMirror загружается вместе с ленивой страницей решения. Доступны JS/TS,
Python, SQL, JSON и Markdown, номера строк, поиск на русском, отмена/повтор и
Ctrl/Cmd+S. Markdown переносится по ширине; длинные строки кода прокручиваются
внутри редактора. Материалы представлены mock-файлом README.md только для чтения.
Обычный ввод фиксирует текст и позицию курсора одной транзакцией CodeMirror:
прокрутка не должна переставлять буквы во время быстрого набора. Публичные
обработчики ввода сохраняют автоскобки и оборачивание выделения; ввод через IME
остаётся нативным. Регрессионные тесты проверяют точный текст до и после обновления.
Поддерживаются загрузка нескольких файлов и папки с сохранением иерархии.
UTF-8 тексты открываются в редакторе; бинарные вложения отображаются безопасным
описанием и скачиваются без выполнения. Код не запускается.

## Сохранение и совместимость

`MockSolutionRepository` хранит проекты под `prodguild.solutions.v1`, отдельно
от существующих `lotty.mock.*.v1`. Каждый проект принадлежит аккаунту и кейсу;
его `status` — `in_progress`, `submitted` или `completed`. Отдельного списка
завершённых кейсов нет: сохранённые завершённые решения доступны из каталога.
Раздел «Ревью» содержит локальные демонстрационные решения и редактор с обсуждениями
(см. [review-demo.md](review-demo.md)); реальные назначения и публикация ревью не выполняются. Списки объединяют
статус проекта с прежним прогрессом пользователя.

При первом открытии прежний текст копируется в `solution.md`. Исходная запись
не удаляется и не переписывается миграцией; чек-лист сохраняется. Повторное
открытие возвращает существующий проект. Прежние завершённые решения остаются
только для чтения. Подготовленный результат для demo/subscription явно помечен
примером; новая отправка никогда не получает автоматическую оценку.

Набор текста сохраняет локальный черновик; «Сохранить» фиксирует версию файла.
Все идентификаторы `sha`/`commitSha` — mock-токены, не настоящие Git SHA.
Сохранение/удаление проверяет ожидаемую версию файла. При конфликте между
вкладками текст остаётся в редакторе: его можно скачать, затем явно загрузить
актуальную версию. Это локальная демонстрация, а не серверная транзакционность.

Отправка сохраняет изменённые файлы, требует хотя бы один непустой файл и
подтверждение пользователя. Чек-лист носит рекомендательный характер. Проект
получает неизменяемый снимок и статус `submitted`; повтор той же отправки
возвращает существующий снимок. Редактор читает отправленные файлы из снимка.
Снимок включает бинарные вложения. Отправленный проект остаётся в «В работе» с отметкой «На проверке».

Ограничения демо: 100 файлов, 200 000 символов на текстовый файл, 1 МБ на загружаемый файл, 4 МБ содержимого файлов с учётом base64
на проект, путь до 240 символов. Папки выводятся из относительных путей;
абсолютные пути, управляющие символы, пустые сегменты, `.`/`..`/`.git` и конфликты
файла с папкой отклоняются. При ошибке записи данные остаются в памяти до
перезагрузки, и интерфейс сообщает об этом. Повреждение хранилища также видимо.

## Переиспользование редактора

`RepositoryEditorComponent` принимает `EditorDocument[]` с иерархическими путями,
выбранный ID, область `scopeId`, текущее содержимое, режим чтения и строку состояния.
Он управляет вкладками документов, breadcrumbs и отображением текста/вложений;
выдаёт события выбора, изменения, сохранения, скачивания и удаления. Опциональный
`showExplorer` включает встроенное дерево файлов. Компонент не знает об аккаунтах,
решениях или ревью. `FileTreeComponent` также можно использовать отдельно, как в
текущей панели «Файлы». История Undo изолирована по файлу и области проекта.

`RepositoryCloneComponent` принимает HTTPS/SSH URL и признак `mock`. Меню «Код»
переключает протокол, копирует выбранную ссылку, закрывается Escape с возвратом
фокуса. Текущий адаптер выдаёт явно обозначенные демоадреса на зарезервированном
`gitea.prodguild.test`; сетевое подключение не выполняется. Реальные URL можно
передать через `cloneUrls` рабочего пространства.

Интерфейс ревьюера, PR Overview, diff и комментарии в эту фичу не входят; редактор
подготовлен к переиспользованию без добавления этих экранов.

## Граница данных

HTTP-запросы сейчас не выполняются. `SolutionRepository` описывает асинхронные
операции; `storeDraft` и `uploadFiles` работают локально. Загрузка набора атомарна:
совпадение путей, неверный путь, превышение лимита или ошибка чтения не добавляют
часть файлов и не перезаписывают существующие. Ошибки хранения явно сообщаются.
Исходный Swagger сохранён без изменений и не используется для текущей UX-итерации.

## Проверки

Из `src/frontend`: `npm ci`, `npm run lint`, `npm run build`.
`tests/e2e/user-solutions.spec.ts` проверяет дерево/редактор, CRUD, загрузку файлов
и папки, бинарные вложения, скачивание, clone menu, вкладки и Undo, перенос данных,
две вкладки, снимки, повреждение хранилища и адаптив. Пользовательские, storage,
sidebar и auth-layout тесты проверяют интеграцию. Дополнительные проверки
разделителя покрывают изменение размеров и сохранность состояния редактора.
Визуальные правила и источники описаны в [brand-ui.md](brand-ui.md).
Полный запуск — по инструкции
frontend skill с явным BASE_URL, свежим сервером и четырьмя viewport.
