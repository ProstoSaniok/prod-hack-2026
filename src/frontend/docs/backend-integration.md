# Связь интерфейса с backend

Актуальные пользовательские страницы работают с FastAPI, PostgreSQL и Gitea.
Backend определяет грейды, права, повышение и начисления; клиент отображает
сохранённые значения. Профиль и политика развития подключены через типизированный
клиент. Файлы участника и метаданные/файлы организатора сохраняются автоматически
через последовательные очереди с проверкой версий.
Старые локальные демонстрации сохранены в исходниках и хранилище, но не используются
в рабочих маршрутах.

## Ручной путь проверки

Frontend запускается через `npm start -- --port 4333`: <http://127.0.0.1:4333/login>.
Backend: <http://127.0.0.1:18080/docs>. Frontend проксирует `/auth` и `/api` на backend;
ответ HTML вместо JSON не является успешным ответом API.

1. Открыть `/admin` по ссылке «Кейсы организатора». Для локального демо включается отдельная сессия организатора, личная сессия участника сохраняется отдельно.
2. Создать кейс с названием, описанием, ожидаемым результатом и компетенцией SQL.
3. Добавить `task.sql` из дерева файлов, записать исходник и дождаться автосохранения.
4. Создать приватный эталон, записать правильный ответ, сохранить, нажать «Эталон готов», затем «Опубликовать кейс».
5. Открыть `/login`, нажать «Исполнитель». В `/catalog` выбрать созданный кейс; проверить, что приватных файлов эталона нет.
6. Нажать «Решать кейс». Адрес станет `/projects/{id}`. Изменить файл и дождаться «Сохранено». Перезагрузка восстанавливает незавершённый черновик.
7. Нажать «Отправить решение»: все изменённые файлы сохранятся автоматически. Ввести необязательный комментарий и подтвердить. Будет открыт `/submissions/{id}`. Ошибка сохранения блокирует отправку.
8. Проверить итоговые и исходные файлы, различия и скачивание отдельного файла. Для проверки пагинации строк сохранить перед отправкой более 100 строк. Обновить страницу: результат остаётся тем же.
9. В `/my-cases/completed` найти работу. После отправки показано «На проверке», после публикации отзыва — фактический вердикт.
10. Вернуться в проект: редактирование и повторная отправка недоступны. Открыть ссылку решения под другой демо-ролью: сервер отказывает в доступе, чужие файлы не показываются.
11. В `/profile` проверить Grade, кошелёк и историю. Профиль использует `/api/v1/me/profile` и `/api/v1/development/policy`; сохранённые грейды, права, обучение и начисления определяет backend. Отзыв и вклад в навыки доступны в карточке решения.

Сервер поддерживает только текстовые UTF-8 файлы. Мутации используют bearer token, `Idempotency-Key` и текущие версии/commit SHA. При сетевой ошибке повтор отправки сохраняет исходные параметры; отмена подтверждения позволяет заново проверить проект. Отправка фиксирует Git-снимок; дальнейшее изменение рабочего Git-репозитория не меняет отправленное решение.

### Проверить ревью и награды

1. Исполнитель публикует решение по SQL-кейсу через описанный выше путь. Работа должна отличаться от исходника.
2. На `/login` войти как «Ревьюер+». У подготовленных формой кейсов порог SQL равен 50, поэтому «Ревьюер−» вправе включить режим, но не получит эти работы. Эксперт требуется для порогов 75 и выше. Решение нельзя выбрать произвольно: его назначает backend с учётом всех навыков и автора.
3. В `/reviews` нажать «Начать ревью». Пустая/неподходящая очередь даёт понятное сообщение; следующий клик выполняет новый запрос. Назначение не имеет дедлайна; его можно продолжить или явно вернуть в очередь с подтверждением.
4. В `/reviews/{assignmentId}` проверить задание, файлы и diff. Добавить оценку 85, вердикт «Принято» и заполнить все три поля обратной связи. Комментарий привязывается к выбранной строке/диапазону pinned-файла, включая неизменённые строки; для удалённого файла выбрать исходник. Добавление комментария сразу сохраняет черновик, даже до заполнения итоговой оценки.
5. Черновик сохраняется автоматически; перед отправкой форма сохраняет актуальную версию. Для публикации нужны все поля обратной связи и согласованный вердикт: принято при оценке >=70, изменения при оценке <70. Незаконченный текст нового комментария блокирует публикацию.
6. «Отправить ревью» → подтвердить. Адрес `/review-results/{id}` показывает неизменяемую опубликованную обратную связь. В `/reviews` она появляется в личной истории. В `/profile` появляется «Награда за ревью».
7. Снова войти как «Исполнитель», открыть соответствующее `/submissions/{id}`: опубликованная оценка, комментарии и вклад в компетенции видны автору. Профиль отражает награду за принятый кейс, решение — вердикт «Принято».
8. При оценке ниже 70 выбрать «Нужны изменения»: отзыв публикуется, положительный прогресс и награда за принятие не выдумываются клиентом. UI получает фактический результат с сервера.
9. При конфликте версии черновик в форме сохраняется. Перед «Загрузить серверный черновик» скопировать нужный текст и подтвердить замену. Закрытое назначение и недостаточные права отображаются как ошибки API. После отзыва прав владелец может вернуть работу, но не читать её защищённые материалы.

Нативные Git-комментарии, редактирование авторского кода ревьюером и ответы/resolve обсуждений не имитируются рабочими API. Экспертный workflow подключён следующим этапом ниже. Старый демо-компонент и его локальные хранилища не удалены; реальные ревью используют серверные черновики и readonly-снимки.

```sh
BASE_URL=http://127.0.0.1:4319 BROWSER_CHANNEL=chrome npx playwright test tests/e2e/review-api-integration.spec.ts --project=desktop --project=mobile --workers=1
```

Для этой проверки нужны ожидающие SQL-решения участника «Исполнитель» с порогом <=74 и без собственного ревью от выбранного ревьюера. Полный `learning-api-integration` создаёт такие решения. Тест не указывает серверу конкретное решение: очередь назначает подходящее по штатной политике. На повторных прогонах число доступных работ уменьшается.

## Экспертная проверка и испытательный период

| Действие                                 | Метод и путь (префикс `/api/v1`)                                  | Операций |
| ---------------------------------------- | ----------------------------------------------------------------- | -------: |
| Источник назначенной экспертной проверки | `GET /review-assignments/{id}/source-review`                      |        1 |
| Решение эксперта по точной редакции      | `POST /reviews/{id}/quality-assessments`                          |        1 |
| Приватные оценки и подробный комментарий | `GET /reviews/{id}/quality-assessments`, `GET .../{assessmentId}` |        2 |
| Отправка исправленной версии             | `POST /reviews/{id}/revisions`                                    |        1 |
| Чтение точной редакции                   | `GET /reviews/{id}/revisions/{revisionId}`                        |        1 |
| Свой испытательный период                | `GET /me/probation`                                               |        1 |

Служебные endpoints, legacy snapshot JSON и отдельный `/me/skills` не вызываются
продуктовым UI, если актуальная проекция уже содержит нужные данные.

Рабочие ссылки: `/reviews` (очередь), `/reviews/{assignmentId}` (обычное либо экспертное назначение), `/review-results/{reviewId}` (результат), `/reviews/{originalAssignmentId}/correction/{reviewId}` (исправление), `/profile` (кошелёк и Grade навыков), `/submissions/{id}` (отзыв и прогресс автора).

### Проверка экспертного цикла

1. Ревьюер с provisional-правами и согласованным испытательным периодом получает обычную работу. Пороги кейса и уровень автора по-прежнему проверяет сервер.
2. Заполнить и сохранить черновик, отправить ревью. Статус — «Ожидает эксперта»; оно ещё не опубликовано автору.
3. Войти как «Эксперт», включить режим и получить работу. Сервер отдаёт экспертные задания раньше обычных при подходящих правах. Экран показывает исходное ревью и неизменяемые файлы решения.
4. Выбрать «Вернуть ревью на доработку», оценку 60 и приватное объяснение; подтвердить. Автор решения не увидит это объяснение.
5. Исходный ревьюер открывает результат в «Мои ревью», читает приватную оценку эксперта и при необходимости открывает оценённую редакцию. Нажать «Исправить ревью», изменить отзыв, сохранить и подтвердить отправку. Создаётся новая неизменяемая редакция и новое экспертное задание.
6. Эксперт получает новое задание, выбирает «Подтвердить ревью», оценку >=70, пишет объяснение и подтверждает. Точный проверенный отзыв становится доступен автору; backend атомарно рассчитывает прогресс и награды.
7. В серверных данных исходного ревьюера обновляется число подтверждений. По текущему контракту требуются три разных ревью; повторные редакции одного ревью не дают дополнительных подтверждений. После трёх успехов сервер подтверждает тот же grant. Профиль показывает сохранённый Grade и XP навыка; список испытательных периодов читается отдельно через `/me/probation`.
8. Автор видит опубликованный отзыв в своей карточке решения, но не приватные экспертные комментарии и отклонённые редакции.

### Локальные демо-данные и ограничения

- Штатный локальный seed дополнен аккаунтами `quality-author.local@example.com`, `quality-author-mobile.local@example.com`, `quality-author-desktop.local@example.com`, пароль `Local-demo-2026!`. Они создаются только при явном `LOCAL_DEMO_SEED=true` на PostgreSQL через существующий seed. Повторный seed не сбрасывает историю, навыки или grants.
- Аккаунт «Исполнитель» получил provisional-права через реальные принятые кейсы и испытательный период через backend. Экспертные E2E предполагают такого ревьюера и отдельного автора с подходящим уровнем. По мере прогонов происходит настоящее продвижение; после завершения испытательного периода тот же ревьюер больше не требует supervision.
- Регистрация создаёт аккаунт, `participant`, welcome-баланс и токен одной транзакцией. Вход дополняет только обычный аккаунт, у которого никогда не было записи `participant`; отозванная или удалённая запись блокирует восстановление. Organizer/admin не дополняются, параллельные входы не дублируют права и бонусы.
- Старые компоненты `cases/reviews` с демо-ответами/resolve и локальными редакторскими копиями сохранены в исходниках. Активные API-экраны не обещают эти функции, поскольку backend их не предоставляет.

Проверка экспертного цикла с настоящими API/PostgreSQL/Gitea:

```sh
BASE_URL=http://127.0.0.1:4319 BROWSER_CHANNEL=chrome npx playwright test tests/e2e/review-quality-api-integration.spec.ts --project=desktop --project=mobile --workers=1
```

Мобильный и настольный экспертные сценарии прошли: ожидание эксперта, приватность автора, возврат на доработку, чтение оценки и редакции, исправление и финальное подтверждение. Серверные queue/completion/quality сценарии: 15 passed. ## Вход в админку и создание дефолтных аккаунтов

Ссылки «Кейсы организатора» на `/login` и `/register` имеют настоящий `href="/admin"`. При обычном клике сначала открывается отдельная organizer-сессия, затем `/admin`; личная сессия участника сохраняется. Ошибка входа остаётся видна на форме, вместо цикла переходов на регистрацию.

Backend CLI автоматически вызывает идемпотентный seed **перед запуском HTTP-сервера**, если явно установлен `LOCAL_DEMO_SEED=true`. Для seed также требуется PostgreSQL и `DEMO_ORGANIZER_PASSWORD`. В `compose.local.yaml` деморежим уже явно включён; повторное предварительное выполнение seed из shell-команды удалено. Повторный запуск не меняет существующие аккаунты и не добавляет повторное welcome-начисление.

На ВМ/в Coolify эти переменные задаются явно для демонстрационного окружения:

```dotenv
LOCAL_DEMO_SEED=true
DEMO_ORGANIZER_PASSWORD=Local-demo-2026!
```

Пароль выше — существующий пароль демонстрационных кнопок; эти аккаунты предназначены для явно включённого деморежима. Шаблон основного окружения и Coolify по умолчанию оставляют режим выключенным. Настройки реальной ВМ в этой работе не менялись и deployment не выполнялся. Автоматическая проверка отклонила автоматическое включение известных паролей для любого PostgreSQL/production-запуска; реализован вариант с явным opt-in.

Отдельные проверки подтверждают: оба auth-экрана ведут в `/admin`; seed на пустой тестовой БД создаёт organizer/performer/review-minus/review-plus/mentor; все роли входят; повторный seed сохраняет те же ID и одно welcome-начисление. `LOCAL_DEMO_SEED` без значения `true` не запускает seed.

not permission. The shell hides review entry points without these rights, and

Progress indicators never invent request

## Grade, баланс и навигация

`GET /api/v1/me/profile` возвращает сохранённые навыки с `grade`, числовым `value`,
правами и испытательным периодом, а также кошелёк. `GET /api/v1/development/policy`
задаёт пороги и условия повышения. Типизированный клиент проверяет эти ответы;
старый backend без этих маршрутов не поддерживает новый профиль.

У каждого навыка отдельная карточка: название, сохранённый Grade и XP. Серверные
`performer`, `review_minus`, `review_plus`, `expert` отображаются как Grade 1–4.
Заполнение отражает XP между текущим и ближайшим обычным уровнем, до Ревьюер+.
Серверный `next_grade` даёт точный остаток XP, успешные кейсы и состояние прошлого
испытательного периода; выполненный числовой порог не даёт новых прав. Для
Ревьюер+ экспертный допуск показан отдельной заявкой. Только сохранённый эксперт
означает максимальный статус. Все полосы и заполнение имеют высоту 28 px.
Градиент заполнения идёт слева направо от `#FFDD2D`; конечный цвет зависит от
сохранённого Grade: `#FFDD2D` для Grade 1, `#FFCE2A` для Grade 2, `#FFC027` для
Grade 3 и `#FFB124` для Grade 4. Цвет зависит от сохранённого Grade, не от XP.
Сохранённый Grade эксперта получает полностью заполненную
золотую полосу с рассеянными светлыми искрами разного размера. Искры плавно
двигаются без наведения, в том числе на сенсорном экране; наведение или фокус
добавляет небольшой разлёт внутри полосы. При reduced motion искры статичны.
Только полосы Grade используют градиент;
остальные поверхности интерфейса сохраняют однотонную заливку.
Достижение порога XP само по себе не включает экспертный эффект и не
меняет серверный Grade. Общего Grade нет; условия следующего уровня приходят с сервера.

Верхняя панель кабинета удалена. Баланс, профиль и выход находятся в sidebar;
ссылка баланса ведёт на `/profile#wallet`. В профиле показывается доступная сумма,
ненулевой резерв и история операций. `/demo-results` и `/demo-results/:id`
перенаправляют на `/my-cases/completed`, не удаляя старые локальные демоданные.
Общий компонент суммы показывает число и предоставленный `logo-currency-v3.svg`,
сохранённый по пути `public/imgs/logos/logo-currency.svg`, вместо видимого названия
валюты в sidebar, профиле, каталоге и результатах. Знак сохраняет пропорции 100:60,
имеет видимую высоту цифр (`0.67em` для Tinkoff Sans) и выровнен с ними по базовой
линии. Текстовая единица
сохранена для скринридеров; в компактном sidebar виден только знак, а сумма
остаётся в подсказке и доступном названии ссылки. Значения, знаки операций и API
не изменяются. Новый `main-logo.svg` используется также как favicon.
Подпись «Кейсы» над меню удалена. Панель и её стрелка на desktop закреплены вместе.
Открытие и закрытие занимает 240 мс: desktop плавно меняет ширину, mobile выезжает
слева с затемнением фона. Фокус, inert и блокировка прокрутки следуют логическому
состоянию меню; быстрое переключение и уход со страницы не оставляют блокировок.
При reduced motion, первом отображении и смене брейкпоинта анимации нет.
Рабочая страница прокручивается целиком, а код и длинное дерево файлов — внутри
редактора ограниченной высоты. Это одинаково для `/projects/:id` и `/cases/:id/work`.

Каталог показывает уровни 1–3 вместо названий квалификации проверяющего. Любой
участник может начать любой кейс. Награда за первое успешное решение — 3 PRODита;
потенциальный XP навыка — максимум P02 (`100 × weight × 1,2`). Точные начисления
появляются после опубликованной проверки. Эксперт продолжает проверять сложные
решения и качество ревью.

## Автосохранение решения

Файлы участника сохраняются на сервер после 800 мс без ввода. Последовательная
очередь проекта хранит исходный SHA, новые правки и точный запрос для повторения
при неоднозначном ответе. Ответ сохранения не пересоздаёт редактор и не очищает
более свежий текст. Ctrl/Cmd+S сохраняет сразу; локальный черновик восстанавливается
после обновления. Конфликт не перезаписывает чужую версию автоматически.

Отправка сначала сохраняет все файлы, получает актуальный HEAD и запрашивает
подтверждение. Ошибка сохранения блокирует отправку. Уход по внутренней ссылке
ожидает сохранение, а при неудаче требует подтверждения. Закрытие страницы
предупреждает только при незавершённых изменениях. Метаданные, материалы и эталоны
организатора используют один последовательный writer, scoped отдельной admin-сессией.
`/admin/new` создаёт неполный серверный черновик при первом вводе, используя сохранённый
client UUID. Переход к `/admin/:id/edit` не пересоздаёт форму и не забирает фокус.
Debounce — 800 мс; неопределённые запросы и локальные буферы переживают reload.
Неверное число сохраняется локально и не мешает записи валидных полей. Готовность
эталона/публикация дожидаются всех правок и затем проверяют полноту данных.

На странице результата остаются название кейса, статус, дата, комментарий автора,
файлы, затем обратная связь и начисления. SHA, версии и JSON-снимок не показаны.

Проверки профиля находятся в `tests/e2e/profile-achievements.spec.ts`, общих
состояний — в `ui-ux-polish.spec.ts`, живого пути публикации и решения — в
`learning-api-integration.spec.ts`. HTTP-фикстуры не заменяют реальную API-интеграцию.

## File-by-file review workspace

`/reviews/:id` now opens changed-file navigation in its files step. Reviewers
select actual old/new line ranges to populate a comment anchor, see saved draft
comments alongside the diff, and can mark files viewed for the current page
session. The full immutable file viewer remains available under «Все файлы». Expanding
code retains the whole files workspace, including comments, draft save and errors.
Selecting an anchor keeps that mode open; switching back to the already opened
full-file viewer preserves its CodeMirror instance.
The feedback step collects the existing score, verdict, strengths, problems and
next steps; final confirmation shows the verdict, score and comment count.

The deployed `/openapi.json` was read on 2026-10-17 from
`https://hack-lead-03-ru-3-vm1-c0e704.vmaas-spirit.t-education.com`.
Existing assignment-scoped GET `/diff` and `/diff/lines` are used through
`LearningService`. Line pages follow the server's `next_offset`, including
byte-bounded pages whose next offset is not 100. Comments retain exactly the
server path, side (`old`/`new`), line and optional inclusive `end_line`; anchors
may include unchanged lines in pinned files. PUT `/draft` still replaces the whole
versioned draft with at most 20 comments of 1000 characters each. Final POST
`/reviews` consumes the saved version after explicit confirmation. No new routes,
mutation formats, credentials, or browser calls to the deployment are introduced.

Unsent comments retain their anchor across file and tab switches. Selecting a
second anchor while text is pending explains how to finish the first comment.
Conflicts retain entered feedback and comments. Refresh restores server-saved
drafts; unsaved text and viewed-file marks are not persisted locally. Inline
comments are reviewer draft entries, not live author replies or resolved threads.

`review-workspace.spec.ts` uses HTTP fixtures for old/new/deleted-line anchors,
file and irregular line pagination, pending text, keyboard selection, save/reload,
conflicts, empty diffs and document overflow across four viewports. Existing
`review-guidance.spec.ts` continues to verify queue and final-confirmation flows.
These checks do not exercise live Gitea or backend publication/rewards.

## Уход со страницы и развёрнутый редактор

Каталог отправляет `q`, `difficulty` и CSV `competency_ids` в GET `/cases`:
навыки соединяются через OR, пустой выбор означает все, фильтрация идёт до

30 секунд только на видимой странице. Чтения не заменяют грязные формы. Постоянные
кнопки refresh убраны, конкретные retry/conflict-действия сохранены.

`LeavePageService` объединяет guards и logout до отзыва токена. Проект пытается
сохранить файлы, ручные формы требуют решения о потере текста. Отмена сохраняет

RemoteFiles/SnapshotViewer на месте до `100dvh`, сохраняя соседний sidebar/mobile

undo, скролл и ожидающее сохранение. Общий expanded-target ревью включает diff,
полный снимок, обсуждения, сохранение и ошибки. Escape сначала обслуживает поиск
